## 📘 Project Description & Architecture

### The Core Concept
An autonomous, data-driven multi-agent media production pipeline that breathes life into static developer materials. The system ingests two raw assets: a silent, unedited application screen recording (`.mp4`) and standard markdown technical documentation (`README.md`). 

Instead of generating basic voiceovers, a multi-modal orchestrator comprehends visual user interface actions in sequence and transforms them into an engaging, high-production, two-character technical discussion podcast. The engine dynamically calculates timing offsets, generating a perfectly synchronized marketing or educational video tutorial where the visuals stretch, freeze, or transition in lockstep with the generated dialogue.

### How It Works (The Multi-Agent Workflow)
1. **The Ingestion & Alignment Agent:** A native multimodal agent parses the timeline of the screen capture, cross-referencing visual events (button clicks, latency lags, layout changes) with the engineering data inside the documentation.
2. **The Scriptwriter Persona Agent:** Takes the structural timeline array and crafts a natural, conversational script adopting two distinct, contrasting personas (e.g., an inquisitive host and a deep technical systems architect).
3. **The Chronos Sync Engine (The Key Innovation):** Rather than guessing text lengths, the script is split into micro-dialogue blocks. Each block is generated via Text-to-Speech (TTS). The system calculates the exact runtime duration of each audio slice down to the millisecond.
4. **The Compiler Agent:** Compiles the video by reading the precise millisecond offsets, dynamically injecting calculated frame-freezes or video-loops into the silent screencast so that the background video stays aligned with the pacing of the spoken podcast discussion.

## 🛠️ Mandatory Technical Stack

To pass the technical screening panel, your code codebase must actively invoke and rely on two required technological layers at runtime:

### 1. The Google Cloud Layer (The Core Brain)
* **Gemini Enterprise:** You must pass your raw video files and text files directly to **Gemini Enterprise** models (such as Gemini 1.5 Pro). Your architecture needs to highlight Gemini's native multimodal token execution—proving that it is analyzing the actual raw `.mp4` visual pixels directly rather than an external text-transcription or static frames.
* **Google Cloud Vertex AI / Agent Builder:** Your application logic should step away from standard, rigid backend routing scripts. Instead, individual prompts must be organized as distinct agents inside a managed agentic workflow framework.

### 2. The Partner Track Layer (Choose at Least One)
To be eligible for the main prize tracks, your system must integrate one of the official technical event sponsors into the application code loop. Given your synchronization challenges, the **ClickHouse + Grafana** path is your strongest engineering option:

* **ClickHouse (Data Logging Layer):** You must show working database connectors inside your repository. As your Python backend generates speech fragments, the exact text inputs, generated audio clip filenames, target video segment lengths, and calculated millisecond offsets (`required_freeze_ms`) must be written to a live ClickHouse table. ClickHouse acts as the real-time time-series index that your video compiler queries to stitch the final frames together.
* **Grafana Labs (Observability Layer):** You must supply a dashboard config or display a live dashboard in your demo video. This dashboard tracks real-time generation metrics: pipeline processing latency, audio-to-video alignment deltas, API token usage costs, and script generation progress bars.
* *(Alternative Partner Option)* **Replit:** If you prefer not to use ClickHouse/Grafana, you can build, test, and host your entire application code loop using **Replit**, explicitly utilizing the **Replit Agent** to generate your user interface or build automated cloud deployment modules for your project.
